# 部署与调整说明 v2

用户入口统一为 README 的“打开工作区并发送提示词”。Agent 从 [完整部署工单](INSTALL_WITH_AGENT.md) 开始，浏览器与旧默认调整见 [Chrome for Testing 工单](CHROME_FOR_TESTING.md)。本文件保留核心技术参考。

## 与当前源工作区一致的流程

- CLI 与 spider_core 按当前源文件逐字节核对，保持 Task、runner、路由、验证、注册与浏览器管理语义。
- web-collection-router 按当次证据选路；需要时侦察接口，然后优先 Python/Node 协议重放、签名/环境复现、多输入对拍和新业务请求验收。
- protocol_ready/protocol_unavailable 互斥；本次已验证协议不因有登录或 JS 被切回浏览器。
- 默认部署 Chrome for Testing 最新 Stable，chrome/9222、tmp/chrome-mcp；只启用 js-reverse，不安装或启用 Cloak。
- spider.py run 是唯一采集执行入口；browser ensure 管理资源；新任务从 experiments 开始，先样本后扩大，不自动注册。
- 普通失败保存脱敏进度后尝试已实现、同授权同数据语义的有界候选；确认验证码暂停整个运行。
- 核心只用标准库，平台依赖就近隔离，运行证据放 runs，凭据和会话缓存按 AGENTS.md 保护。

## 新部署核心

在新目录解压，在含 spider.py 的根目录执行：

```powershell
py -3.11 scripts/verify_distribution.py
py -3.11 scripts/agent_platform_compat.py setup --json
py -3.11 scripts/agent_platform_compat.py doctor --json
py -3.11 spider.py list --json
py -3.11 spider.py run experiments/example_local/collector.py --task experiments/example_local/task.example.json
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run_full_regression.ps1
```

注册表初始为空，示例 completed/complete/3；这是离线基础层。继续按工具链文档安装/配置并完成真实连接验收，才算完整工具栈部署。
setup 会重建本机 Skill 发现链接；已存在错误链接或真实目录时报告冲突，不覆盖。不要复制原电脑的 junction。

## 平台入口

| 平台类型 | 规则与 Skill | MCP |
|---|---|---|
| 支持 AGENTS.md | 根规则、.agents/skills | 按当前宿主规范加载生成定义 |
| Claude 类 | CLAUDE.md、.claude/skills | 支持时合并项目 .mcp.json |
| Gemini 类 | GEMINI.md、.gemini/skills | 支持时合并项目 settings |
| 其它 Agent | 显式读取规则与相关 SKILL.md | 按当前官方文档/本机帮助映射 command 和 args |

生成器保留两项兼容定义，默认只合并 js-reverse；不使用会写入两项的 --write-project-mcp，不改用户全局配置。Codex 等使用 TOML/CLI 的宿主应先查看本机当前 mcp add/配置帮助，再映射生成定义；不要将 JSON 直接当 TOML 或覆盖整个用户配置。
宿主自动发现规则/Skill/MCP 的能力必须现场核验。安装了文件不代表当前已开始的会话会热加载。

## 系统和身份检查范围

当前源浏览器身份核验依赖 Windows CIM，非 Windows 上保守返回不匹配。macOS/Linux 可先做核心离线与 symlink 检查，浏览器层需实现并验证相应进程身份检查，不能绕过它来宣布部署通过。
浏览器配置 v2 需要两个候选，未安装的一项用本项目不存在的 unconfigured 路径，明确报告不可用。浏览器本体由目标机器提供，不附带来源不明二进制。
端口被其它项目占用时不接管、不终止别人的浏览器、不共用日常 Profile。

## 分层验收

| 层 | 验收依据 |
|---|---|
| 分发 | ZIP CRC / manifest；不是第三方签名 |
| 核心 | 完整回归、离线 3 条示例、初始空表或升级后保留原表 |
| 依赖 | 实际版本、安装输出、pip check、JS 构建入口 |
| 浏览器 | 端口、程序和本项目 Profile 匹配 |
| MCP | 初始化、tools/list、list_pages 只读调用 |
| Playwright | 从同一配置连接、合成页面读取通过 |
| Agent | 新连接读规则/Skill、实际 MCP 工具调用 |
| 真实业务 | 新任务样本、来源对拍与完整性；本次部署不执行 |

输出各层独立状态，未做项写 false，不能借用旧电脑或历史运行结果。工具链安装后日常任务不重复安装、不自动升级依赖。新增 pytest/Node 测试必须被完整回归覆盖，缺运行时则明确失败。
