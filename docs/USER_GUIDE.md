# 安装与日常使用

Spider Workbench 是给 coding Agent 使用的数据采集与 Web / JavaScript 逆向工作区。用户用自然语言说明目标，Agent 按项目规则组织任务、实施分析、执行采集、验证数据并整理交付。

## 安装只需交给 Agent

将下载、完整解压后的项目文件夹作为 Agent 工作区打开，然后发送：

> 请阅读 README.md、AGENTS.md 和 docs/INSTALL_WITH_AGENT.md，完成这个工作区的部署。先检查已有环境，自动补齐依赖，从官方安装最新 Stable Chrome for Testing，使用项目独立 Profile、Chrome/9222 和 js-reverse MCP，不安装或启用 Cloak。保留已有任务与配置，完成各层验收后告诉我实际结果。部署所需的常规可逆安装、构建与项目配置调整已授权，请连续推进。

后续步骤由 Agent 按[部署工单](INSTALL_WITH_AGENT.md)完成，无需用户逐条执行终端命令。Agent 应有本机文件、终端和配置工具的能力；账户登录、系统权限或宿主重连等确实需要用户操作的部分，应说明具体原因和下一步。

完整浏览器部署优先 Windows。Python 3.11、完整 Node 24+/npm 和浏览器由 Agent 检查、复用或按官方来源安装；macOS/Linux 浏览器进程归属核验仍需适配，下载成功不等于浏览器层已验收。Agent 账户由用户准备，源码不提供模型账户或 API Key。

## Agent 部署时会做什么？

| 阶段 | 验证内容 |
|---|---|
| 盘点并保留工作 | 已有任务、配置、运行数据和依赖环境 |
| 核心与 Skills | 源码清单、Skill 入口、离线三条合成记录及数据校验 |
| 工具层 | 项目隔离依赖、JSReverser 构建和本机启动定义 |
| 浏览器层 | 官方最新 Stable Chrome for Testing、独立 Profile、程序/端口/CDP 归属 |
| MCP 与宿主 | 初始化、工具目录、只读调用、Playwright 合成页面、Agent 实际工具调用 |
| 验收 | 完整回归、真实分项结果与必要待办 |

默认浏览器候选为 chrome，CDP 为 http://127.0.0.1:9222，Profile 为项目 tmp/chrome-mcp；MCP 使用 js-reverse。旧版 cloak 配置槽位可作为未启用兼容占位保留，不需要安装或验收 Cloak。

最新 Stable 在首次部署或明确升级时查询；日常任务复用已验收版本。现有 bootstrap 安装器负责隔离工具，Chrome 的官方下载与配置由 Agent 按工单继续执行；不会因一条依赖安装命令结束就虚报全部已接通。

## 已经部署过，怎么调整？

在原项目打开 Agent，发送同一部署提示词即可。Agent 应先复用通过的阶段，按[浏览器调整工单](CHROME_FOR_TESTING.md)切换默认配置，并保留旧程序、Profile、任务、数据和其它 MCP 设置。

如果还需要升级框架文件，按[保留式迁移](MIGRATION.md)比较差异，不直接把新 ZIP 解压覆盖旧项目。换电脑重新生成本机路径、环境和配置，不复制登录态、虚拟环境或 node_modules。

## 日常任务怎么描述？

> 帮我从这些页面采集最近 7 天文章，字段为标题、原文、发布时间、作者和来源链接。先做 5 条样本让我确认，确认后采集指定范围，输出 Excel 和 JSON，说明遗漏与失败，保留进度，不自动注册能力。

需求中说明网站入口、时间/数据范围、字段、数量或结束条件及输出形式。Agent 先看已有能力与本次证据，没有适配就创建独立 experiment；根据需要做浏览器观察、本地请求验证、样本对拍和正式运行。

网站需要登录时，在项目专用浏览器中完成。不要将密码、Cookie、Token 写进 Task 或 Issue。确认出现验证码时，Agent 保存进度、说明触发位置并暂停，按项目规则等待针对本次运行的明确指示。

## 结果和进度在哪里？

| 目录 | 内容 |
|---|---|
| outputs/ | 最终交付文件、分析报告、部署验收报告 |
| runs/本次运行/ | normalized.jsonl、validation.json、collector_result.json，以及任务支持的检查点和运行材料 |
| experiments/任务名/ | 当前任务实现与非敏感配置 |
| tmp/ | 本机工具缓存、浏览器程序、独立 Profile、隔离后端 |

合成示例只验证框架运行，不是网站采集结果。真实任务需要 Excel、JSON 或其它格式时，Agent 按需求生成并检查，告知实际文件路径和覆盖范围。

任务中断时，先让 Agent 读取本次运行状态和检查点，说明已完成范围，再按该采集器支持的方式续跑。不要删除 runs 来重新开始；不同采集器的恢复方式以实现和任务合同为准。

## 如何判断完成？

部署报告会区分离线核心、依赖、浏览器、MCP、Playwright、Agent 实际加载和完整回归。未执行项应说明原因；配置写入或脚本初始化通过，不能替代宿主实际调用。

业务交付还需看来源一致性、必填字段、唯一键、数量与结束条件。不能证明全量时，报告应明确为样本、部分或未知，不能只凭 HTTP 200 或退出码为零判定完成。

## 给客户如何交付？

| 客户需求 | 推荐方式 |
|---|---|
| 有 Agent，想自己开发和运行任务 | 本源码与部署提示词，完成本机验收后描述任务 |
| 技术人员维护采集器 | 源码、Task 合同、依赖声明与运行证据 |
| 只要固定网站的操作软件或数据 | 另行实现并验收对应任务，交付桌面程序、启动包或结果文件 |

本项目不附带所有网站的现成功能。对外承诺安装后点击采集时，还需要完成具体网站适配、客户操作界面、依赖打包和业务验收。

出错时将错误类别、版本和当前状态交给 Agent，保留现场。技术参考见[排错](TROUBLESHOOTING.md)、[浏览器/MCP](BROWSER_MCP.md)与[框架说明](框架与Skills说明.md)。
