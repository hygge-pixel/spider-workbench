# 工具链补齐与旧包升级实施计划

目标：保留当前工作区采集流程，补齐可部署的 JSReverser MCP、Playwright CDP 与本地 Python/Node 工具链，并为已部署 v1 的机器提供保留式升级。

不迁移网站 collector、历史运行、凭据、Profile 或源机器路径。CLI 和 spider_core 以当前工作区为基准逐字节核对。

1. 按原 v1 ZIP 建立独立 v2 副本，保留旧 manifest 作为升级三方比对基线。
2. 编写升级保护及 MCP 合并失败测试，确认旧任务、注册表、本机配置、冲突文件及升级后新增工作不会被覆盖。
3. 加入本机工具链配置、启动器、stdlib MCP 初始化/只读调用探针及 Playwright CDP 连通性检查。
4. 带上当前 JSReverser 2.0.3 的最小可构建源码快照、依赖锁和许可证；排除案例、数据、依赖和运行材料。只为运行输出增加隔离目录适配。
5. 提供当前实际使用版本的 Python 工具依赖声明，以及 Playwright CLI 的独立安装声明；不复制环境、不全局安装。
6. 更新默认工具栈为 Cloak/9232 优先、Chrome/9222 显式候选；缺少 Cloak 时明确记录兼容模式，不把 Chrome 冒充 Cloak。
7. 写可独立发送的《已部署旧版的调整工单》，覆盖盘点、备份、dry-run、冲突合并、工具接入、验收和回滚。
8. 完成新解压目录的框架回归、真实安装/构建、两个独立空 Profile 的 MCP 与 Playwright 验收；测试只使用本机合成页面，不访问真实站点。
9. 模拟已部署 v1：加入新任务、注册记录、本机配置和用户修改，执行升级、重复升级、回滚及并发修改保护测试。
10. 校验 ZIP/manifest、原核心一致性、源工作区未改动，交付完整 v2 ZIP 与独立升级文档。
