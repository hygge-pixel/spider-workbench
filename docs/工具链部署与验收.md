# 浏览器、MCP、Playwright 与协议工具链部署

用户入口见 README；本文件供 Agent/维护者执行和排错。默认浏览器部署按 [Chrome for Testing 工单](CHROME_FOR_TESTING.md)，只启用 js-reverse MCP。

## 1. 声明和安装位置

| 工具 | 声明/位置 | 源工作区基线 |
|---|---|---|
| Python | 本机解释器，隔离工具环境 .venv-toolchain | 3.11 |
| Node/npm | 本机完整安装 | 已测 24.16.0，要求 24+ |
| Python Playwright | requirements-collection.txt | 1.57.0 |
| requests / httpx / curl_cffi / bs4 | 同上 | 2.32.5 / 0.28.1 / 0.13.0 / 4.15.0 |
| pytest | requirements-dev.txt | 8.4.2 |
| JSReverser | vendor/js-reverse-mcp | 当前使用的 2.0.3 源码快照、npm lock、许可证 |
| Playwright CLI | toolchain/playwright-cli | 0.1.18，独立 npm lock |
| Babel | 根 package.json 和 lock | 保留原包版本，AST 辅助使用 |
| Chrome for Testing | Agent 从官方下载完整 chrome | 部署时最新 Stable，chrome/9222 |

Python 直接版本对齐源环境；传递依赖以解析和 pip check 为准。npm 使用固定 lock。浏览器/Python/Node 本体不塞进源码 ZIP。
JSReverser 的 SOURCE_SNAPSHOT.json 保存所拷源码原始哈希；这是当前已安装程序的源码快照，不声称等同于未经核验的上游 tag。分发适配包括运行目录隔离及依赖修补；本地改动在 CHANGELOG 与来源声明中单独记录，原始快照哈希只代表输入基线。

## 2. 安装依赖和构建

目标 Agent 先发现 Python 3.11、完整 Node 24+ 的真实路径。以下 $nodeExecutable 由目标机器实际发现，不能照搬源电脑路径。

```powershell
# 默认只输出命令计划，不安装
py -3.11 scripts/install_browser_toolchain.py --component all --node $nodeExecutable
# 在已授权范围内执行本次安装
py -3.11 scripts/install_browser_toolchain.py --component all --node $nodeExecutable --apply
```

可按 python / mcp / cli / ast 分项执行；all 同时覆盖这四项。Python 环境新建/复用 .venv-toolchain，不改旧项目的 .venv；MCP 与 CLI 在各自子目录安装，不全局安装。
安装器显式跳过 Puppeteer/Playwright 浏览器下载。MCP 先 npm ci --ignore-scripts，再运行随包的 prepare 和 build；prepare 只调整该 MCP 新依赖目录的已知文件。
安装器不安装 Node 本体，不下载 Cloak，不改变系统代理/证书。缺 Node 时由目标 Agent 使用受信任来源安装或选择已有版本。

```powershell
$toolPython = (Resolve-Path -LiteralPath '.venv-toolchain/Scripts/python.exe').Path
& $toolPython -m pip check
```

已有隔离环境满足版本也可复用，记录真实版本。不把安装成功当连接成功，下载失败保留包名/错误，不放宽 TLS 或改用不明来源。

## 3. 配置独立浏览器

唯一来源仍是 config/workspace_browser.json。初始不存在配置时：

```powershell
& $toolPython scripts/agent_platform_compat.py configure-browser --candidate chrome --executable $chromeExecutable --json
& $toolPython scripts/agent_platform_compat.py set-default --candidate chrome --json
```

已有真实设置不同则先备份审核，只更新本项目相关项。Chrome 参数不携带 Cloak 的指纹或环境配置。Cloak 不安装或启用，Chrome 是正式默认部署。
配置 v2 要有两项候选；未安装的一项保留不存在的 unconfigured 路径，不伪装就绪。

```powershell
& $toolPython spider.py browser status --candidate chrome --json
& $toolPython spider.py browser ensure --candidate chrome --json
```

初始离线 status 可未启动；ensure 才会管理浏览器资源。必须核验端口/程序/本项目 Profile；端口被其它项目占用时不要接管或终止它。
Profile 必须独立：tmp/cloak-mcp、tmp/chrome-mcp。不得复制旧电脑会话或日常个人 Profile，也不加 --no-sandbox。

## 4. 生成准确 MCP 配置

默认构建入口 vendor/js-reverse-mcp/build/src/index.js。生成器记录实际工具 Python/Node：

```powershell
& $toolPython scripts/browser_toolchain.py configure --python $toolPython --node $nodeExecutable
```

结果为 config/agent_tools.local.json 和 runs/_mcp/generated/mcp_config.json。服务关系：

```text
js-reverse       → start_js_reverser.mjs --candidate chrome → 配置中的 127.0.0.1:9222
js-reverse-cloak → 历史兼容定义，本次不启用
```

历史候选由同一程序实现，当前只部署 chrome。Node 启动器先调用短时 Python 预检核验浏览器归属，然后在宿主管理的同一个 Node 进程导入 MCP；不留下额外的长时 Python 包装进程，不自行安装或偷偷开启另一套浏览器。SPIDER_MCP_RUN_DIR 和 REMOTE_DEBUGGING_URL/PORT 都按当前候选设置，运行材料在 runs/_mcp/<服务名>，不污染 vendor 源码。

生成器默认只输出 js-reverse。按实际宿主合并；--write-project-mcp 仅用于支持 mcpServers 格式的项目配置。不自动启用旧 js-reverse-cloak。保留其它服务；同名冲突先审核、备份，按 JSON/TOML 或本机 CLI 正确映射。配置只放程序路径/参数，密钥使用环境变量。

## 5. MCP 真实检查

```powershell
& $toolPython scripts/browser_toolchain.py mcp-smoke --candidate chrome --stdio-only
& $toolPython scripts/browser_toolchain.py mcp-smoke --candidate chrome
```

第一条只验初始化和 tools/list，read_only_tool_passed=false 是预期；第二条先核对浏览器身份，再调用 list_pages。
脚本不保存页面标题、URL、Cookie 或 MCP 原始载荷。protocol_initialized=true、read_only_tool_passed=true 才说明所测浏览器链路通过。
源码内部 serverInfo.name 可能沿用 chrome_devtools，配置服务名仍是 js-reverse-cloak/js-reverse，这不代表连错服务。
然后让目标 Agent 重连/新会话，实际看到并调用一次工具；命令行探针通过不能替代宿主加载验收。

## 6. Playwright CDP 真实检查

```powershell
& $toolPython scripts/browser_toolchain.py cdp-smoke --candidate chrome
& $toolPython examples/playwright_cdp.py --candidate chrome
```

关键连接为 playwright.chromium.connect_over_cdp(配置中的cdp_url)。脚本先核对归属，仅创建并关闭自己的合成页面，不关闭已有页面或共享浏览器。
不访问真实网站、不导出登录态；合成页面成功只证明连接/执行/读取可用，采集仍走 collector 与 spider.py run。
默认仅验收 chrome；Cloak 连接为 not_required。每项按本次实际证据记录。

## 7. CLI、Babel 与其它工具

```powershell
& $nodeExecutable toolchain/playwright-cli/node_modules/@playwright/cli/playwright-cli.js --version
```

CLI 版本与 Python Playwright 版本分开记录。接入 CDP 前查看本版本 --help，不默认 open 另启一套浏览器。collector 仍主要使用 Python Playwright。
all 已按根 package-lock 安装 Babel；分项时可用 --component ast，再用合成输入验收通用 Babel 脚本；不复制原机器 node_modules。
Reqable/AdsPower/REA/IDA/WireMCP/WEDECODE 等按任务需要接入，保留候选池地位，不变成每次任务必经步骤。

## 8. 完整检查与记录

```powershell
& $toolPython scripts/agent_platform_compat.py setup --json
& $toolPython scripts/browser_toolchain.py doctor
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run_full_regression.ps1 -PythonExecutable $toolPython -NodeExecutable $nodeExecutable
& $toolPython spider.py run experiments/example_local/collector.py --task experiments/example_local/task.example.json
```

输出分层部署报告，记录安装版本、真实候选、MCP/CDP/宿主加载状态、升级保留检查和剩余限制。日常任务不运行安装器、不自动更新依赖。
本包当前原生浏览器进程核验以 Windows 为基线，非 Windows 需适配并验证相应身份检查，不能跳过后声称通过。
