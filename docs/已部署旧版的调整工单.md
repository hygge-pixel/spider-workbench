# 已部署昨晚 v1 的项目：保留式升级到 v2

这份文档可以独立交给已经部署 v1 的 Agent。目标是补齐工具接入层，并与源 Spider 流程保持一致，不重装、不清空现有工作区。
推荐同时提供 SpiderFramework_v2_完整工具链框架_20261017.zip。文档可独立阅读；下面的自动升级命令需要这个 ZIP 中的新脚本和源文件，不能拿旧包中的同名路径假装已经补齐。

## 1. 你正在接收的调整任务

用户已经部署过 v1。请在那个现有项目上增量调整，不另建替代项目后宣布完成。先读取其现有规则和实际状态，再对照本工单。
本次已授权检查环境、校验新版、升级框架文件、隔离安装声明依赖、构建 MCP、接入指定独立浏览器、合并两项 MCP 服务和合成数据验收；这些可逆常规步骤连续推进。
不做真实网站批量采集、不复制旧电脑会话、不扩大账号权限、不提交 Git、不发送通知、不改变模型与审批设置。

## 2. 必须保留的内容

- 你昨天部署后新增/修改的实验、collector、任务、说明和业务文件。
- 当前 platforms/registry.json 及已注册能力，不能用新版空表覆盖。
- runs、outputs、tmp、.venv 等现有数据、运行、环境、Profile 和缓存。
- config/workspace_browser.json 的本机程序路径、Profile，以及有意设置。
- config/agent_tools.local.json、现有 MCP 其它服务、Gemini/Claude/Codex 的其它设置。
- 本机凭据和登录态原地保留，不读取内容、不复制到新版包、报告或新位置。

新版 ZIP 的空注册表只供新部署。不要删除这些内容来让 manifest 或测试变绿。

## 3. 先建立两个独立目录

把新版 ZIP 解压到现有项目之外的独立暂存目录。不要解压到现有项目根直接覆盖，也不要放在现有项目子目录后执行自动升级。
令 $releaseRoot 指向新版解压后含 spider.py 的 SpiderFramework，$targetRoot 指向昨天真正部署的项目根；两者不能相同或嵌套。

```powershell
# 两个变量使用本机实际目录，不使用源电脑路径
py -3.11 "$releaseRoot/scripts/verify_distribution.py"
py -3.11 "$releaseRoot/scripts/upgrade_framework.py" --target $targetRoot
```

首条验证新版原始文件；第二条默认 dry-run，只输出 changes/conflicts/preserved，不写项目。
检查当前 Git 状态（若有 Git）、注册表/任务目录和浏览器配置的结构与文件哈希；不要把凭据内容写入盘点报告。

## 4. 处理冲突，再执行升级

升级器用 v1 原始 manifest、v2 manifest 和目标文件哈希三方比较：

| 情况 | 行为 |
|---|---|
| 目标仍是旧版原文件，新版有改动 | 计划更新，先备份旧文件 |
| 新增文件且目标不存在 | 创建新文件 |
| 目标已是新版 | 跳过，可重复执行 |
| 新旧版本该文件未变化，目标有本机修改 | 保留，不干涉 |
| 新版要改，而目标也被你改过 | 报冲突，默认整次不写 |
| 要新增/更新的文件位置已有同名目录，或父路径被本机文件占用 | 预览即报冲突，保留原目录/文件，整次不写 |
| 任务、注册表、本机实际配置和运行目录 | 始终保护，不覆盖 |

conflicts 非空时逐项比对。常见是 AGENTS.md、README、.gitignore 或你定制过的脚本。保留你的有效本机规则，并合入本工单与新版关于工具链/验收的内容。
人工合并完成后，使用 --accept-local 指定已经审核的文件；它只是保留你完成的合并结果，不是自动解决冲突。不要把冲突路径批量加入来逃过检查。

```powershell
py -3.11 "$releaseRoot/scripts/upgrade_framework.py" --target $targetRoot --accept-local AGENTS.md
# 计划无未处理冲突后执行；按实际已审核文件重复 --accept-local
py -3.11 "$releaseRoot/scripts/upgrade_framework.py" --target $targetRoot --accept-local AGENTS.md --apply
```

若没有冲突，不需要 accept-local。升级器将旧版被替换文件备份在目标 outputs/framework-upgrade/<唯一编号>/，输出 backup 路径；不备份/搬走本机凭据与会话。
执行前后检查受保护文件哈希不变，并记录主动人工合并的文件。不要直接 Copy-Item -Recurse -Force 覆盖整个项目。

## 5. 升级后的框架结构应具备什么

- 原 CLI/spider_core/Skill 与唯一采集入口继续使用。
- 新增 requirements-collection.txt、requirements-dev.txt、vendor/js-reverse-mcp、toolchain/playwright-cli。
- 新增 install_browser_toolchain.py、browser_toolchain.py、start_js_reverser.mjs、upgrade_framework.py。
- 新增 examples/playwright_cdp.py 和完整工具链说明。
- 现有 task/collector/注册能力继续存在；不导入源电脑历史能力，不拿新版空表覆盖。

## 6. 安装工具，保持旧环境

进入 $targetRoot；发现本机 Python 3.11 与完整 Node 24+/npm，令 $nodeExecutable 为真实 Node 程序路径。

```powershell
Set-Location -LiteralPath $targetRoot
py -3.11 scripts/install_browser_toolchain.py --component all --node $nodeExecutable
py -3.11 scripts/install_browser_toolchain.py --component all --node $nodeExecutable --apply
$toolPython = (Resolve-Path -LiteralPath '.venv-toolchain/Scripts/python.exe').Path
& $toolPython -m pip check
```

隔离环境 .venv-toolchain 与旧 .venv 并存。日后仍是这个 Python 执行 spider.py run，不增加第二个采集 runner。
安装器使用锁文件构建 MCP，跳过浏览器自动下载；不全局安装所有工具。安装失败报告实际包名/错误，不宣称整套部署成功。
若你已有同等独立工具环境且验证了版本，可以复用并记录，而不是复制环境目录。

## 7. 对齐浏览器：保留本机路径和 Profile

优先 Cloak/9232 与独立 tmp/cloak-mcp；Chrome/9222 是显式候选。不要把前一台电脑的可执行路径或登录态搬过来。
已有有效浏览器配置先保留，不重新 configure 覆盖。缺 Cloak 的未配置槽位且本机已经有可信 Cloak 程序时：

```powershell
& $toolPython scripts/agent_platform_compat.py configure-browser --candidate cloak --executable $cloakExecutable --merge --json
& $toolPython scripts/agent_platform_compat.py set-default --candidate cloak --json
& $toolPython spider.py browser ensure --candidate cloak --json
```

完整新配置没有时可去掉 --merge 首次创建。已存在真实槽位参数不同则人工审核保留，合并源工作区基线所需参数，见工具链文档。
Cloak 未安装时先明确 Chrome 兼容模式；不安装来源不明二进制，也不把 Chrome 放到 Cloak 槽位后声称完全一致。
候选端口/Profile 必须核验；有冲突保留现场，不终止其它项目浏览器。

## 8. 补齐 MCP 配置与 Agent 加载

```powershell
& $toolPython scripts/browser_toolchain.py configure --python $toolPython --node $nodeExecutable
```

先检查生成的 runs/_mcp/generated/mcp_config.json，实际服务名为 js-reverse-cloak 与 js-reverse，由同一 JSReverser 构建入口实现。
项目 JSON 宿主可用 --write-project-mcp 合并，仅管理这两项，保留其它服务和顶层设置。同名不同配置先审核，需要更新这两项时才用 --replace-managed。
Codex/TOML/其它格式宿主按本机当前帮助，将生成 JSON 的 command/args 转为该平台支持格式；不全文件替换用户级设置。
启动器先检查项目浏览器，再以 stdio 启动 MCP；先执行 browser ensure，不能让它接错浏览器。API 密钥不进入 JSON；基础浏览器操作不要求配置额外 LLM Key。
配置变更后重连或新建会话，确认该 Agent 的工具目录真能看到并调用 list_pages；配置写入不等于当前会话已加载。

## 9. 按层验收，不能只重跑离线 3 条

```powershell
& $toolPython scripts/agent_platform_compat.py setup --json
& $toolPython scripts/browser_toolchain.py doctor
& $toolPython scripts/browser_toolchain.py mcp-smoke --candidate cloak --stdio-only
& $toolPython scripts/browser_toolchain.py mcp-smoke --candidate cloak
& $toolPython scripts/browser_toolchain.py cdp-smoke --candidate cloak
& $toolPython examples/playwright_cdp.py --candidate cloak
& $toolPython spider.py run experiments/example_local/collector.py --task experiments/example_local/task.example.json
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run_full_regression.ps1 -PythonExecutable $toolPython -NodeExecutable $nodeExecutable
& $nodeExecutable toolchain/playwright-cli/node_modules/@playwright/cli/playwright-cli.js --version
```

如果当前只部署 Chrome，显式换候选并报告兼容模式。完整复现要求默认 Cloak 路径通过。两项候选分别记录，不能互相推定。
Playwright 检查只创建并关闭自己的合成标签，不触碰真实业务页面。MCP 探针不保存标题/URL/Cookie或原始工具载荷。
旧项目已新增的实验测试也要运行；不能删除新任务或测试来满足空框架假设。注册列表可能非空，这对升级后的项目是正常现象。
运行材料与新验收输出留本机，不打回源码包。

## 10. 核验原工作流没有改变

用你的规则和一个实际新任务计划确认：先按证据路由；需要时浏览器观察；本地重放/对拍后优先 Python/Node 协议；必要部分浏览器补采；spider.py run 唯一采集入口；先小样本；确认验证码暂停；不自动注册。
本次只验证框架和合成数据，不必挑一个真实网站批量跑来证明安装。工具可用不等于任意网站已通过。
规则中不得仍写“仅核心通过就算整套部署完成”或把安装所有专项 MCP 当每次任务必经流程。

## 11. 回退与完整性说明

框架回退使用升级器输出的 backup 路径：

```powershell
py -3.11 "$releaseRoot/scripts/upgrade_framework.py" --target $targetRoot --rollback $backupPath --apply
```

它只恢复本次更新的框架文件/移除本次新增且仍未改动的文件，不递归删除用户目录。若升级后这些文件有新工作，回退整体停止并报告，不覆盖新内容。
依赖安装、浏览器启动、人工规则合并、MCP 两项配置变更不属于这个自动回退；单独按你记录的差异恢复，保留其它用户配置。工具环境可原地保留，不为回退清理用户环境。
新版 manifest 代表官方发布文件。接受过的本机合并、原有任务和配置均需如实报告；不重算官方 manifest 假装原始一致。首次完整性检查应对独立解压的新包执行，目标自定义差异另列。

## 12. 最后交给用户的报告

输出 outputs/deployment_acceptance.md 和 JSON，列出：目标目录/系统、Python/Node及包版本、升级变更和备份、人工合并项、受保护文件保留检查、默认候选与模式、MCP构建/stdio/只读调用、Playwright CDP、Agent实际加载、完整回归与离线3条结果、未执行项。
至少字段：core_offline_passed、existing_work_preserved、mcp_stdio_passed、mcp_read_only_call_passed、playwright_cdp_passed、agent_mcp_loading_verified、default_browser_candidate、source_workflow_mode、external_targets_tested、limitations。
本机真实成功才写 true；缺工具、下载失败、宿主未重连、非 Windows 身份检查未适配都应明确列出。
